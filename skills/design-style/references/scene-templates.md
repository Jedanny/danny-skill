# 场景模板

先定场景，再定风格。模板决定结构和密度，风格只决定表达方式。

## landing page

- goal：快速解释产品价值，建立第一印象，并推动一次清晰转化。
- required sections：hero、核心价值点、产品能力分组、社会证明、CTA 收口。
- optional sections：产品演示、价格概览、FAQ、对比竞品、创始人/团队背书。
- information-density rules：首屏只保留一个主要叙事；中段用 3 到 5 个能力块；底部再补细节，不要一开始就把所有特性堆满。
- component guidance：hero 需要一个主 CTA；能力区优先卡片、标签、短句标题；社会证明区要统一样式，不要混 logo 墙和长 testimonial 墙。
- anti-slop warnings：不要做成“每一屏都像首屏”；不要重复三次同一句价值主张；不要同时出现三种卡片语言。

## product page

- goal：让用户理解某个具体产品、功能包或套餐为何值得选择。
- required sections：产品概述、关键功能、使用方式或流程、定价或方案、CTA。
- optional sections：适用人群、案例、集成能力、常见问题、迁移说明。
- information-density rules：比 landing page 更具体，但每个区块只回答一个核心问题；定价与功能差异要并排可扫读。
- component guidance：功能区适合图文并列、流程分步、对比表；CTA 要和购买/试用动作一致，不要在同页混多个主目标。
- anti-slop warnings：不要把 marketing 文案和 help center 文案混在一起；不要在产品页里塞完整公司介绍；不要用空泛插画代替功能说明。

## dashboard

- goal：帮助用户快速判断状态、发现异常并完成高频操作。
- required sections：顶层状态、核心数据区、主任务入口、列表或明细区。
- optional sections：筛选器、趋势图、提醒中心、快捷操作、空状态引导。
- information-density rules：首屏优先看状态而不是装饰；数据卡数量保持克制；图表与列表要有主次，不要每块都抢注意力。
- component guidance：卡片要有统一边界和数值层级；图表只保留支持决策的最少图例；列表操作要靠近数据本体。
- anti-slop warnings：不要把营销 landing 的大留白照搬进后台；不要用过度渐变影响读数；不要把所有操作都藏在右上角菜单里。

## mobile app screen

- goal：在有限空间内完成一个明确任务，并保持触达路径简短。
- required sections：顶部上下文、主要任务区、关键操作、反馈状态。
- optional sections：底部导航、辅助说明、次级推荐、空状态、权限提示。
- information-density rules：一屏一个主要任务；文字要短；同层级操作不超过 3 个显著按钮；优先竖向节奏而不是横向塞满。
- component guidance：按钮、输入框、标签和列表项要统一尺寸节奏；底部区域适合放主 CTA 或导航，不要两者都抢主位。
- anti-slop warnings：不要把网页卡片原样缩到手机里；不要混用多套圆角、阴影、图标笔触；不要依赖长段文案解释操作。

## presentation / one-pager

- goal：在短时间内说清一个提案、产品概念或战略更新，并留下可复述的主线。
- required sections：标题结论、问题/机会、方案摘要、证据或亮点、下一步。
- optional sections：市场背景、路线图、风险、客户声音、附录。
- information-density rules：每个 section 只保留一个结论句；一页里只能有一个主视觉中心；图表和文字不要同时过满。
- component guidance：适合使用大标题、短结论、编号流程、对比表和单张重点图；强调句要有稳定的字体和色彩规则。
- anti-slop warnings：不要把网页布局直接截图式搬过来；不要为了“高级”把字号压得太小；不要在一页里混演示文稿语气和官网语气。

## 使用顺序

- 先选最接近输出物的模板。
- 再用风格参考决定配色、排版、边界感和情绪。
- 如果用户需求横跨两个模板，先明确主模板，另一个只作为局部补充。
